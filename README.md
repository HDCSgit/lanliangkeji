## 五、电商交易系统

### 5.1 交易流程

```
1. 浏览产品 → 选择规格/数量 → 加入购物车
2. 进入购物车 → 确认商品 → 去结算
3. 填写/选择收货地址 → 提交订单
4. 选择支付方式:
   ├── 微信支付 → 扫码支付 → 模拟支付成功
   ├── 支付宝 → 扫码支付 → 模拟支付成功
   └── 对公转账 → 查看收款账户 → 转账 → 上传凭证截图
5. 支付完成 → 查看订单 → 等待发货
```

### 5.2 订单状态机

```
[pending_payment] 待付款
      │
      ▼ (支付成功)
    [paid] 已付款
      │
      ▼ (审核通过 / 管理员发货)
 [processing] 处理中 ──→ [shipped] 已发货
      │                      │
      ▼                      ▼
 [cancelled] 已取消    [in_transit] 运输中
      │                      │
      ▼                      ▼
 [refunded] 已退款    [delivered] 已送达
                              │
                              ▼
                        [completed] 已完成
```

### 5.3 对公转账审核流程

**用户端:**

1. 选择「对公转账」支付方式
2. 查看收款方开户行账户信息
3. 完成线下转账
4. 上传转账凭证截图（支持 JPG/PNG，最大 10MB）
5. 提交后显示「交易处理中，等待审核员处理」

**审核员端:**

1. 登录管理后台 → 进入「转账审核」
2. 查看待审核的转账凭证列表
3. 点击查看凭证大图
4. 点击「通过」或「不通过」
   - 通过 → 订单变为「已付款」状态，可上传快递单号发货
   - 不通过 → 填写原因 → 用户收到通知可重新提交

**时限规则:**

- 首次提交后 72 小时内有效
- 审核不通过后，72 小时重新计算
- 超过 72 小时未提交/重新提交，订单自动取消

### 5.4 订单付款邮件通知

订单**付款成功后**，系统自动通过 QQ 邮箱 SMTP 给系统管理员发一封邮件通知，包含三个关键信息（订单号、收件人+手机号、收件地址），方便管理员第一时间安排发货。

**邮件触发点**：`_mark_paid_and_settle` 函数（统一支付成功处理入口），支付宝回调、对公转账审核通过、人工标记支付成功 都会走到这里。

**邮件内容预览**：

| 字段 | 示例 |
|------|------|
| 订单号 | LL202606250001 |
| 收件人 | 张三 |
| 手机号 | 13800138000 |
| 收件地址 | 福建省 厦门市 思明区 莲前西路 123 号 |
| 支付方式 | 支付宝 |
| 订单金额 | ¥299.00 |

**配置方法**（在 `server/.env`）：

```bash
# QQ 邮箱 SMTP 配置
SMTP_HOST=smtp.qq.com          # 推荐用 QQ 邮箱,其他邮箱改对应 SMTP 地址
SMTP_PORT=465                  # 465 = SSL, 587 = STARTTLS
SMTP_USER=your-sender@qq.com   # 发件邮箱
SMTP_PASSWORD=授权码           # ⚠️ 不是登录密码,见下方
SMTP_SENDER=蓝亮科技 <your-sender@qq.com>   # 显示的发件人,可留空用 SMTP_USER
ADMIN_NOTIFY_EMAIL=1244716205@qq.com        # 收件邮箱(管理员)
```

**QQ 邮箱授权码生成步骤**：

1. 登录 QQ 邮箱网页版 → **设置** → **账户**
2. 找到 **POP3/IMAP/SMTP/Exchange/CardDAV/CalDAV服务**
3. 开启 **SMTP服务**（首次开启会要求短信验证）
4. 点 **生成授权码** → 短信验证 → 复制 16 位授权码
5. 粘贴到 `SMTP_PASSWORD`

**容错设计**：
- 任一 SMTP 字段缺失 → 静默跳过，**不影响支付主流程**
- 发送失败（网络/授权码错误）→ 捕获异常记日志，**不影响支付主流程**
- 邮件失败也不会回滚数据库事务

**不发邮件的常见情况**：未配 `.env` 里的 SMTP_* 字段，或 `ADMIN_NOTIFY_EMAIL` 留空。控制台会输出 `[email_service] SMTP 配缺失,跳过订单 XXX 的邮件通知`。

## 六、手机端导航特性

### 6.1 公司名称滚动隐藏/显示

手机端（小屏幕）顶部导航栏中的公司名称标题具备智能滚动响应：

- **向上滑动页面**（内容向上滚动）：公司名称标题平滑隐藏，为页面内容腾出更多可视空间
- **向下滑动页面**（内容向下滚动）：公司名称标题重新显示，方便用户识别品牌
- 桌面端保持常显，不受滚动方向影响

### 6.2 涟漪按钮效果

导航栏中的按钮（购物车、用户菜单、移动端菜单按钮等）添加了 Material Design 风格的涟漪动画：

- 点击时从触点位置扩散出波纹
- 增强交互反馈，提升移动端点击体验

### 6.3 非首页导航样式

当用户位于非首页或页面滚动超过阈值时，导航栏自动切换为更醒目的样式：

- 白色半透明背景 + 背景模糊
- 海洋主题渐变底部边框（蓝 → 青 → 蓝）
- 更强的阴影效果
- 文字与图标颜色切换为深色，确保可读性

## 七、本地开发

### 7.1 一键启动（推荐）

项目根目录已提供一键启动脚本，会同时打开两个 PowerShell 窗口分别运行前后端：

```powershell
# PowerShell 方式（推荐）
.\start-services.ps1

# 或 CMD / 双击运行
start-services.bat
```

启动后会看到两个窗口：

- `Backend - FastAPI`：后端服务 `http://localhost:8000`
- `Frontend - Vite`：前端服务 `http://localhost:5173`

关闭这两个窗口即可停止服务。

### 7.2 手动启动后端

```powershell
cd server
$env:PYTHONIOENCODING='utf-8'
.\venv\Scripts\activate
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

### 7.3 手动启动前端

```bash
cd app
npm run dev
```

### 7.4 构建

```bash
cd app
npm run build
```

## 九、最近修复记录(2026-06-17)

| 修复项 | 影响 |
|--------|------|

| **deploy.sh 自动降级 vite 7.3+** | build 前自检,发现 7.3+ 自动 `npm install vite@~7.2.4 --no-save` 强制降级,部署自我修复不依赖 lockfile |
| **移除未使用的 `Eye` import** | 修 TS6133 编译错误导致 build 失败 |
| **整张商品卡片都可点击进详情** | 之前只有"了解详情"小链接和 hover 才显的"查看详情"按钮能点,普通区域点不动 |

| **修规格单价/运费 input 输不进小数的 bug** | 修后管编辑产品规格时小数点无法输入 |
| **库存只在付款成功时扣减** | 之前创建订单就预扣库存,未付款订单会一直占用库存导致库存数据不准 |
| **对公转账"前端展示"checkbox 改即时切换** | 跟支付宝/微信支付方式 toggle 行为保持一致(之前是表单一并保存) |

| **ProductImage 首屏 priority 图优化** | 加 `fetchPriority="high"` + `decoding="sync"` + 不再 `opacity-0` 隐藏,避免首屏空白 |
